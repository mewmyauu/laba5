## Главные выводы

1. `if/else` позволяют программе принимать решения и выполнять разный код в зависимости от данных. Для сложных условий их удобно комбинировать с операторами `&&`, `||` и `!`.

2. `switch/case` читается лучше длинной цепочки `if/else if`, когда одна переменная сравнивается с несколькими конкретными значениями. Несколько `case` подряд позволяют объединять значения в одну группу (дни недели, сезоны). Чем гуще лес тем if else..

3. Тернарный оператор `? :` сокращает простое ветвление «одно из двух» до одной строки, но для сложной логики лучше использовать обычный `if/else`.

4. Пользовательский ввод нужно проверять: `int.TryParse()` и проверка диапазона защищают программу от падения и от некорректных данных.

## Ответы на вопросы

**1. Чем `int.TryParse()` безопаснее `int.Parse()`? В каких случаях стоит использовать каждый?**

`int.Parse()` выбрасывает исключение `FormatException`, если строка не является числом, и программа аварийно завершается. 

`int.TryParse()` в таком случае возвращает `false` и не падает, поэтому программа может сообщить об ошибке и запросить ввод заново. `TryParse` стоит использовать, когда данные вводит пользователь и они могут быть неверными (как в игре «Угадай число»). `Parse` подходит, когда формат гарантирован (например, в учебной задаче на ввод целых чисел или при чтении заведомо корректного файла).

**2. Когда `switch` удобнее, чем цепочка `if/else if`? Приведите пример из реальной жизни.**

`switch` удобнее, когда одна переменная сравнивается с набором конкретных значений: код короче и нагляднее. 

Пример из жизни: 
1. Меню банкомата (1 — баланс, 2 — снять деньги, 3 — пополнить, 4 — выход);
2. Кнопки лифта, где по номеру этажа выполняется своё действие. 

В лабораторной таким примером были меню и определение сезона по номеру месяца.

**3. Что произойдёт в `switch`, если убрать `break` после одного из `case`?**

В C# компилятор выдаст ошибку: выполнение не может «провалиться» из одного `case` в следующий, если ветка содержит код. 


Это отличает C# от C и C++, где без `break` выполнялись бы и следующие ветки. Без `break` можно оставлять только пустые `case`, идущие подряд, они объединяются в одну группу.

**4. Чем отличается `=` от `==` в C#? Почему это частая ошибка?**

`=` — оператор присваивания, он записывает значение в переменную. `==` — оператор сравнения, он возвращает `true` или `false`. 

Ошибка частая, потому что символы похожи, а в обычной математике знак `=` означает «равно». 

В C# `if (x = 5)` для `int` не скомпилируется, так как присваивание даёт число, а не `bool`. Но для логической переменной `if (flag = true)` компилируется и меняет значение переменной вместо проверки.

**5. Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.**

Можно. Пример на основе итогового сообщения в игре «Угадай число»:

```csharp
string result = attempts <= 7 ? $"отлич результ; всего {attempts} попыток" : $"число найдено {attempts}";
```

Читаемость приемлема только при двух-трёх уровнях и аккуратном форматировании в столбик. Если условий больше или в ветках сложные выражения, код становится трудным для чтения, и лучше использовать `if/else if` или `switch`.
